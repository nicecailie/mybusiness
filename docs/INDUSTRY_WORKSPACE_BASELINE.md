## Existing paths to reuse

- write/scoped, membership locks, audit/outbox, RLS, exact amount/quantity helpers and immutable balanced journals.
- Supplier, PurchaseOrder/PurchaseLine, GoodsReceipt/Lines, SupplierBill, FinancePayment; receivePurchase/createBill/settle in core.ts. Existing endpoints remain compatible.
- Receipt increases debit inventory/credit goods-received-not-billed; bill transfers that amount to AP; payment debits AP/credits cash/bank. Paying is never a stock or running-cost event.
- Existing financialReport/branchPerformance are journal-derived, but cash is only net movement and equipment categories do not exist. ExpenseCategory name-only; Expense posts all costs to 6000.
- POS/offline sale and return logic remains authoritative. Restaurant payment uses postSale; hotel stays currently post no revenue. These are preserved until phases C/D.
- Industry ID is provisioned server-side from onboarding input. No industry-change API exists; existing business update schema is strict and permits only nif/tva/offlinePolicy. Preserve rejection of industry changes rather than inventing a destructive conversion.
- Navigation/dashboard are globally assembled with partial module filtering. Core panels contain English-only copy and accounting terminology. docs/INDUSTRIES.md incorrectly calls restaurant/accommodation unavailable despite live source implementations.

## Phase A implementation plan

1. Extract existing purchase/save, receive, bill and settlement transaction bodies into shared helpers; add atomic purchase-entry, receive+auto-bill and order-payment commands using those helpers. Keep original contracts/endpoints and expected results.
2. Add category kind + expense posting-account snapshot, additive migration and default categories. Equipment debits an asset, not running costs. Reversals use the original recorded posting account.
3. Extend journal-derived finance with cash in/out, current owed totals and one source-linked spending list; expose it through a plain-language Money view.
4. Add one purchase list with ordered/received/paid columns, inline supplier, multi-line partial receipt, payment box and history drawer; all new labels live in shared en/fr messages. Preserve unrelated CorePanel functionality.
5. Drive direct links/cards from the industry catalog and actual role/module permission intersection. Keep expert accounting behind More. No specialist placeholder pages.
6. Add business-logic/HTTP/browser tests, run all requested checkpoints, update industry catalog documentation and create implementation/file/manual reports. Finish the current phase before starting another; document the precise stopping point.

## Accounting assumptions requiring business review

Equipment is an asset without depreciation (A). Restaurant stock remains deducted at payment (existing policy; C). Hotel revenue-at-check-out and guest deposits held until billing are D targets, not current behavior. VAT remains unconfigured until B policy work; no new tax rate is assumed.
